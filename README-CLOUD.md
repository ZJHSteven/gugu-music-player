# v3.3.8 iPhone / Owlbear 窄屏高度修复

- 修复手机端 Owlbear 较高的插件浮窗只显示上方约 320px、黄色音频启用按钮被裁切、下面大片空白的问题。此前触屏 CSS 强行将 `.app` 限制为 320 CSS px，并补了 150px 空白滚动区；现在直接使用 iframe 实际高度的 100%，滚动由内部 `.main` 承担，保留 iOS 安全区。
- 该修复只涉及 CSS 布局与版本号，不修改音频传输、缓存、歌单 Metadata、DO 中继和预测播放逻辑。

# v3.3.7 新增：重新录制版本可确认替换、当前曲/下一首优先

- GM 补传音频时，文件大小或 SHA-256 不同不再立刻拒绝：先在歌单内显示带原/新摘要的风险警告，只有点击「确认替换版本」才把新文件用**新的 SHA-256** 写入浏览器缓存，并只更新该歌在 Metadata 里的文件摘要、大小及可读时长；旧 SHA-256 的文件不能被覆盖，取消操作不会改变歌单。若其他 GM 在确认前已经更改原曲目版本，取消这次旧确认，要求重新检查。
- 正在播放的歌曲若替换为重新录制版本，玩家可能需要重新加载，且新音频的片段时序可能不同。因此保留统一播放时钟锚点，但不保证不同录音内容能够在同一时间位置无缝衔接。
- 晚进入的 PLAYER 优先检查并请求当前正在播的歌曲，其后按播放顺序预取下一首，再补历史歌曲；避免首次大歌单完整本地 SHA-256 扫描拖延第一批缺失文件的请求。仍采用 **256 KiB 分片传输、整文件 SHA-256 校验完成后播放**，并非未校验的分片流式边下边播。

# v3.3.6 新增：音频健康检查与恢复

- GM/DM 打开房间时校验已有歌单结构和本机逐首音频大小、SHA-256。发现本机缺失或损坏的文件，歌单上显示红色「原文件缺失」标记，可点击补传按钮，选择与该曲目 SHA-256 完全一致的原文件；不会新建重复曲目或影响其他歌曲播放。
- 玩家仍优先请求当前和后续要播放的音频。连接刚建立时等待短暂发现窗口，确认无在线音源或多次传输失败后，通过 Owlbear Broadcast 提醒房主；音源重新出现后告警会自动清除。播放预测和低频时钟校准沿用原有逻辑，不改为逐秒服务器同步。
- ZIP 导出会核对本机所有原文件；ZIP 导入严格验证版本、结构及 CRC/SHA-256，对有效的缺文件备份允许安全部分恢复，分别报告成功、已存在、同名不同文件、ZIP 内缺失及房间仍缺失的曲目。
- 云版不再提供自动 B 站 / YouTube 抓取或 HTTPS 直链输入。GM 可使用 [Parabolic（yt-dlp 图形版）](https://github.com/NickvisionApps/Parabolic/releases) 等外部下载工具取得音频后上传。原先导入的 `kind=url` 歌曲仍可正常播放。
- 原始音频由各浏览器的 OPFS/IndexedDB 保管，并可按需经过 DO 临时中继；房间歌单和播放状态存在 Owlbear Metadata，容量较大时通过 DO 快照保存。Cloudflare DO **不持久保存音频原文件**；用户手动下载的 ZIP 才是包含音频与歌单的离线备份。

# 咕咕点歌台云端版 · 安装与测试

> 开发提示（2026-11-19）：v3.2.2 对手机音频连续播放进行专项改造；正式上线前需完成真实 Android/Safari 设备验收。同步采用设备时钟标识和 Owlbear 元数据，不依赖每秒 DO 播放轮询。

**本地音乐备份**：云版的音频存放在浏览器私有缓存中，并非云端持久存储。GM 可在「设置 → 歌单备份与恢复」生成并下载完整 ZIP（含歌单及原始音频）；换设备或清理缓存后，使用「从 ZIP 恢复」补回音频及缺失歌单。请务必将 ZIP 真正下载并保存在浏览器数据之外，生成下载链接本身还不算备份完成。单个 ZIP 最大内容约 256 MiB，建议分批整理较大的歌单。

**晚加入玩家的缓冲**：优先取正在播放的音频，其他歌曲最多同时预取一首；目前仍须收到完整文件并校验 SHA-256 后才能播放，尚未实现任意格式的 Range 流播。

## 在线入口

- Owlbear 插件清单：`https://music.zjhstudio.com/manifest.json`
- 网页入口：`https://music.zjhstudio.com/`
- Cloudflare Worker：`gugu-music-cloud`

将 **插件清单完整 URL** 添加为 Owlbear Rodeo 自定义扩展，再在房间打开咕咕点歌台。
GM 将本地音频拖入“添加”页，音频优先保存到当前浏览器 OPFS，
其他玩家在缺少该文件时通过同一房间的可休眠 DO WebSocket 获取。
曲目和播放/暂停状态由 Owlbear Room Metadata/Broadcast 同步。

**重要：** 房主在当前设备原始歌曲清理前务必另行保存离线备份！
浏览器可能自动删除站点存储、用户也可能主动清理缓存；任何成员都不在线时，
**DO 没有任何音频备份可供恢复**。文件分发只在至少有一个在线持有者时成功。

## 平台和版本范围

| 项目 | 当前状态 |
|---|---|
| Windows / macOS Chrome、Edge、Firefox | 设计支持 OPFS，失败回退 IndexedDB；未全部真机逐端验收 |
| iOS / Android Safari、Firefox、Chromium | 设计适配；后台页面与音频自动播放还需真机验收 |
| 浏览器内直接上传歌曲、歌单分类、播放控制 | 云版已实现 |
| B 站链接抓取、在线音频提取 | 原版依赖 Node，纯云版暂不可用 |
| 文件分块、哈希、自动按需获取 | 已实现；浏览器隔离环境 3 MiB 和本地 DO 30 MiB 测试通过 |
| DO 休眠 | 使用 `ctx.acceptWebSocket()`，不设 DO 内定时器，等待 Cloudflare Runtime 决定休眠 |

## 开发验证

```pwsh
npm ci
npm run test:cloud
npm run build:cloud
npm run verify:cloud
npx wrangler dev --local --port 8790
```

其中 `verify:cloud` 是无需联网的静态构建检查；`verify:cloud:online`
会真正请求正式域名并验证 CORS。某些 Windows 本机网络环境的 Node.js
不使用系统代理，此时在线子命令可能因连接超时失败；应使用 CDP
浏览器跨源 fetch 或系统 PowerShell 请求独立复核，而不是把超时误认为
清单格式错误。

启动另一个终端进行真实本地 DO 中继测试：

```pwsh
$env:GUGU_RELAY_URL = 'ws://127.0.0.1:8790/relay'
node tests/cloud/relay-smoke.mjs
```

在浏览器打开以下地址，模拟 GM 和玩家（`dev=1` 仅模拟 SDK）：

- `http://127.0.0.1:8790/?dev=1&role=GM&room=test-123`
- `http://127.0.0.1:8790/?dev=1&role=PLAYER&room=test-123`

网页会使用相同的测试房间元数据；也可以用 CDP 独立 BrowserContext
模拟不同设备的存储隔离，验证实际走 DO 同步音频而非共享一个浏览器缓存。

部署：
```pwsh
npm run deploy:cloud
```

部署前请先确认当前 Cloudflare 账号、域名和 wrangler 配置，不要误部署到其他账号。

## 成本与传输边界

Cloudflare Worker 只负责静态文件与连接升级。每房间一个 DO 实例，
每个已打开网页占一个 hibernatable WebSocket；闲置无音频传输时无持续
音频流、无周期应用心跳。DO 的握手、入站消息及运行期间仍可能计费，
休眠期间不累计计算时长费用。

当前每个块 256 KiB，最大单音频 64 MiB。文件只有在本地完整校验后才写入
OPFS/IndexedDB。本地空间不够、无在线副本或网络断开均可能导致歌曲不能播放。
